## 阶段 1｜10 月 1–3 日：数据纵切与基线

依赖：G0 已明确计分可用范围。

- 云端先验证两个相邻开发月的输入与导出，再扩到 6–12 个开发月；建立逐月 SCE 发布日历。
- Event MCP 有权限则先查小样；无权限时直接使用可审计的官方宏观发布数据。新闻不足不阻塞基础版。
- 固定历史 P；E 先用价格、劳动市场、政策少数信号。先跑“截止时点最后公布值”的基线。
- 产物：`data/processed/` 输入快照、`data/evaluation/` 真值、study 内 P/E 构建器和基线。
- **G1**：能回答每条输入为何在当时可知；未来/未知发布时间输入被拒绝；基线可重算。近期无法取证的资料明确隔离。

## 阶段 3｜10 月 9–13 日：开发试验、冻结正式方案

依赖：已通过云端流程与本地重算验收（或等价本地路径）；真实调用预算已确定。

- 只用开发/验证期调试 prompt、失败处理、模型和人口规模；完成同输入单次 LLM 对照。
- 根据实测 token 量测算正式实验、消融和重试的总预算；设总额和请求数上限。核对模拟 LLM 的实际 ID、固定修订、训练/后训练截止及工具权限；按[模型时间泄漏协议](MODEL_TEMPORAL_LEAKAGE.md)限定历史回放的论文主张。
- 补齐正式窗口的 P/E；冻结目标、as_of、人口版本、测试期、对照、消融、主要指标与配置哈希。
- **G3**：正式测试之前保存冻结记录；没有证明历史版本的数据不进入主要历史预测实验。候选 2020–21 开发、2022 验证、2023–24 测试仍待此时正式锁定。
