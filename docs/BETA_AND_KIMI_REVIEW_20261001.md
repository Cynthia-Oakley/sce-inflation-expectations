# Beta 计分差异与 Kimi 工作重点复核

核查：2026-10-01，Codex。范围：用户指定的四份工作记录、计分源码、v3 归档、导出工具与关键测试。**原 `scoring/sce_q9.py` 未修改；没有新云端操作、MCP 请求或模拟 LLM 调用。**本文是独立复核，不是正式研究目标变更。

## 一、结论与建议

1. 现有计分方法的主要分支和研究方向正确，Beta 差异有具体实现原因，不能简单归咎于模型或数据质量。也不能把这些差异全称为“小数精度误差”。
2. 独立候选方法有所改善，但尚未完全复现官方输出。建议继续 SCE 主线、保留原始 Q9，不为这个问题立刻切换主目标，也不等待完全复刻才推进历史 P/E 和真实 B 的小试准备。
3. Kimi 的版本保留、费用未知标注、真实 LLM 暂缓和唯一源码方向符合项目规划。需优先修复导出工具的结果删除风险，并补充 v3 代码与日志格式不一致的解释。

## 二、Beta 差异：定位到了什么

### 1. 零概率档的处理是一个主要来源

现实现用最外层正概率档之间的**所有**内部边界拟合累积概率，包括中间为零的档。独立实验改为仅使用正概率档的右边界（按通胀值从低到高排序），保持支持端点由原始档位定义，**不移动区间、不重分配概率**。

在已有的 2020-01、2022-06 两个月中，闭合支持且中间有空档的全部 13 条记录：原实现个人均值绝对误差中位数约 0.2431 个百分点；只改变上述边界选择后约 0.000006，13/13 均小于 0.001。这是很强的实现差异证据，但官方文档未明确写出这一细节，仍属数据支持的复现假设。

不能把“CDF 中省略某些拟合点”推广成“模拟回答可以删除零概率档”：原始十档必须完整保存。也不能只保留容易拟合的人来报告全国指标。

### 2. 形状下界和开放尾部约束也影响结果

原实现使用 α、β≥1，形状上限 200，并强制开放右尾端点>12、左尾端点<-12。独立候选实验使用 α、β≥1.001，仍保留支持范围±38，但允许估计的尾端点缩入名义尾部边界，始终要求左端<右端。

这些是**诊断候选约定，不是已经证实的官方参数**。官方方法附录规定了开放端估计与±38外限，未完整给出程序约束、优化起点和停止规则。官方公开均值/四分位数的逆向诊断发现，部分输出可由尾端点缩入±12的 Beta 曲线重现；逆向诊断不能证明纽约联储实际用了该组参数。

192 条分层样例的均值误差≤0.001记录数：原实现90；仅跳过零档125；再用1.001形状下界153；再放松尾部内限169。把形状上限200提高到2000仍为90，不能解决问题。改成档概率平方损失仅35条达标、允许形状参数<1仅72条达标，均不支持作为修复方向。

这些候选约定是在已经看过的计分对账数据上诊断得到；不是预注册算法，不得把改善当作未见样本的验证结果。

### 3. 有些开放尾回答不能唯一确定均值

例如按问卷顺序 `[20,40,40,0,0,0,0,0,0,0]`：只有两个内部累计概率约束，却需要估计两个形状参数和一个右端点。保持原有约束，只改变尾端初始值14、20、30、37，均可找到平方损失低于1e-20的解，但均值分别约9.3767、9.2210、9.3573、9.3884。

因此，“优化损失几乎为零”不足以保证与官方密度均值相同。正式计分需固定解的选择规则，并记录不可识别/多解敏感性；随意增加起点或迭代次数不能补出缺失的官方规则。本轮候选全量结果中154条数值 Jacobian 秩不足，只作诊断标记，不直接等同于154条全部存在同样程度的均值不确定性。

### 4. 还发现一个分位数数值问题

当前本地 SciPy 1.17.1 / NumPy 2.4.6 中，`betaincinv(1.0000000000000013, 1.0000000000000002, .75)` 返回约0.875；独立对CDF求根得到约0.75。它会影响四分位数/IQR，不解释用解析公式计算的均值偏差。独立诊断脚本已用 `brentq` 对CDF求根；原计分器保持未动。后续修复应增加 `CDF(quantile)≈p` 检查，不能仅假定换库版本即可解决。

## 三、完整两月核对：改善的范围

在全部1,780条有效 Beta 回答上对比原实现与“跳过零档拟合点 + 1.001形状下界 + 放松尾部内限”候选，误差单位均为百分点：

- 个人均值绝对误差≤0.001：**1197/1780（67.2%）→1500/1780（84.3%）**。
- 个人均值绝对误差95分位：约 **0.4623→0.3186**；最大误差 **3.8686→3.0145**。残余误差仍不可忽略，尤其影响异质性/尾部研究。
- 闭合连续档642条：两版均641条达标；闭合空档13条：0→13；开放连续档1059条：555→789；开放空档66条：1→57。
- 月度加权中位数相对官方公开指标的差：2020-01 **+0.006798→+0.006778**；2022-06 **+0.011067→+0.005258**。个人拟合改善不保证月度中位数同步显著改善。
- 2022-06本地计分有效1201人、官方有效1202人，故总体差还包含样本纳入规则差异。官方全有效样本中位数6.775855；官方字段限制到共同有效样本后为6.768528。不得将全部全国差异归因于Beta。
- 所有候选求解器都报告成功，但仍存在上述误差：成功状态不等于官方复现成功。本轮没有扩展到60个月，也没有看Agent预测表现来选方案。

## 四、怎样处理剩余问题

**建议采用的推进方式（需用户决定是否正式采用候选计分）：**

1. 继续保存模拟 Q8/Q9 原始回答；计分留在本地独立模块，暂不替换平台或原计分器。
2. 用限定工作时段向纽约联储寻找/询问原始实现，问题具体包括：CDF拟合点是否跳过零档；α/β下界；开放端内外限；初始值/优化器/容差；多解选择；不收敛及异常回答处理。原始代码未找到；不要无限期阻塞项目。
3. 如无法取得完全一致的实现，冻结一版明确命名的“Q9近似密度指标”。同一计分器同时处理模拟问卷和真实问卷，并同时报告与官方headline的差异，从而区分行为误差与计分误差。不得用真实headline加常数校正后再宣称官方算法。
4. 同时比较原始十档分布、直接由档概率计算的事件概率等无需密度拟合的指标，Q8仍作为独立辅助指标。它们各有统计含义，不能冒充官方Q9 headline。
5. 正式使用前在预先选定、尚未用于本轮诊断的计分核验月份复查覆盖、均值/IQR、异常分支、全国和分组统计及尾部敏感性。不要为得到更好的Agent测试成绩改计分或换目标。若最终只能改主目标，由用户与导师明确决定。

本轮候选的目的在于定位问题，**不建议现在直接复制为生产修复**。允许尾部缩入会让部分正概率档位于拟合支持之外，必须在方法说明中解释这种近似取舍；论文作者的独立实现甚至采用不同约束，无法作为“纽约联储官方源码”代替。

### 优先修复的两处工程问题

**P1：重新导出会删除已有运行产物。** `scripts/export_study_runtime.py` 的 `export()` 只检查标记后直接 `shutil.rmtree(target)`，再复制源码；排除trajectory等目录仅约束复制来源，不能保护目标里已有结果。独立临时目录实验已证实：放入`trajectory/valuable_run.json`，再次导出后文件消失。当前真实副本尚是骨架，未据此发现用户已丢数据；但必须在真实运行前修复。建议运行输出放独立run_id目录，导出工具遇到派生结果/未归档改动时拒绝覆盖，或使用新的版本目录；新增“结果不得被重导出删除”的测试。

**P2：v3归档代码与JSONL格式存在断点。** 归档`model.py:73`写入的是字面量`\\n`（两个字符），不是换行。独立提取该方法在临时目录对两条Observation执行，得到0个LF和2个字面量`\\n`；取回文件却有40个LF且没有字面量`\\n`。API与对话取回的model.py哈希相同。因此，当前代码不能直接产生当前日志的行格式。可能是执行后修过日志、运行加载的代码与落盘代码不同等，需要Kimi查明并记录转换/运行源码版本，不能直接断言伪造，也不能继续写“证据链完全闭合”。已有文件哈希自洽和40条回答内容匹配仍成立。

最省额度的处置：先查已有本地回执，不为旧版本反复消耗云端对话；仍无记录则保留缺口，新运行在decision入口保存输入并封存运行源码哈希、日志和转换记录。

- `0.55/-0.03`等规则系数、收入调整和Q9哈希模板只有流程用途。虽然上一月回答已放入Observation，scripted B没有读取它，因此尚未验证跨月预期更新或P/E对Q9的行为作用。不得把v3完整报告等同于完整小研究。
