## 用户确认的推进方向（2026-10-11，新闻分配尚未实现）

- **关键词负责宽松粗筛，LLM负责按明确背景和规则精筛。**不为少数争议案例增加关键词特例，只修普遍适用的明显词形错误和类别遗漏。精筛保留编号、格式及少量语义抽查，重点统一提示词定义，不追求逐篇人工裁决或零误筛。原v1.2规则、提示词及响应不覆盖，后续修改另留版本。
- **内容合格不等于每个人都会看到。**159篇`keep`是跨三个窗口的候选，先按各自日期窗口整理同一事件的重复和新进展；65篇背景可少量留用。尚未形成新每月清单，公共库约50篇仍是候选规模，不是每个家庭的阅读数量。
- **分别处理新闻的重要程度与个人接触。**影响较广的生活价格、就业及政策事件可作共同背景候选；具体新闻按主题、地区及家庭消费、住房等已有特征增加被选中概率，同时保留随机接触，避免租客只能看房租或低收入者只能看食品。画像与阅读偏好的对应关系是机制假设，不是已测得的真实阅读记录；不从人口特征猜政治立场或政策信任。
- **按用户随后确认，共同背景以实际总头版A1为准。**从存档中同时满足`print_section=A`和`print_page=1`的文章抽取，财经版B1不当作总头版；共同层不再按通胀相关性精筛，以免因调查主题倒推居民关注内容。版面缺失保留为未知，不让LLM猜头版。所有Agent共用抽取的共同层是第一轮机制假设，A1不等于每位美国居民真实读过。
- **先做离线示例，再登记真实模拟。**离线样例采用共同3条＋个人5条（仅示例，不是已冻结条数或真实注意力参数），展示不同画像收到的原标题、摘要及必要原文片段。用固定种子及主题、地区、画像规则生成个人选择，保留新闻编号和选择依据。全部遵守各线现有信息窗口；语义标签不能修复未知历史文本版本。随后比较同条数的统一、随机及按P分配视图，先看接触差异是否形成，再看总体与分组误差；不用真实SCE答案挑选新闻或调分配。

较早的`information_exposure.py`试验路由价格且关闭新闻；本轮新闻分配另在`news_exposure_demo.py`离线实现，未接入正式Simulation。正式E/模型/计分配置保持历史版本，未来真实调用另按具体输入、接收方及预算确认。

## 摘要去重与真实模拟接入（2026-10-11，核查与候选计划）

**不会把相同摘要喂两遍。**审核区分别展示NYT原始`abstract`与`snippet`，用于核查来源，不能视为实际请求。现有v2模拟提示只读标题与摘要；新离线新闻视图在片段等于摘要、或片段已包含在摘要中时不再追加。18组已保存输入共涉及38篇独立新闻，34篇两字段相同，核查重复发送违规0；重新渲染与已保存输入一致。对于部分重叠但不完全包含的文字，当前并未做语义压缩，后续仍要检查重复强调。

**准备做真实API对照，但现在只有离线新闻部分，尚未接入完整P/E/B和引擎。**建议依次完成：

1. 补齐5/6月粗筛候选中尚未精筛的部分，建立完整公共库；按同一事件减少重复报道，保留真正的新进展。不需要为了精筛做到零误判。
2. 复用已有真实开发样本与篮子，替换三个完全合成演示家庭；生成并检查完整P/E/B提示，确认旧30条新闻没有从其他通道再次进入，保留实际消息与来源哈希。模型、温度0.5、问卷、数值E、人口和计分方法保持同一版本。
3. 先登记三组同条数对照：所有人共享同一组额外消息／个人均匀随机抽取／按P提高相关消息概率并保留随机性。三组共用同样的A1共同背景、公共候选库和文字呈现；共同3＋个人5可作候选，最终条数、人数和种子需在完整提示核查后冻结。旧30篇结果仅作背景，不拿其与8篇输入的差异直接归因于人口匹配。
