# NYT Archive 覆盖、as_of 与扩展审计

审计日：2026-10-07。范围仅为本地 NYT Archive 缓存、`scripts/build_nyt_events.py`、E v2 的 NYT 读取逻辑与可访问的 NYT 官方文档。未读取 `.env`/API key，未调用 NYT API，未下载数据，也未改代码。以下缓存数字是扩展运行前的盘点快照；并行新增下载或输出不作为本报告验收结果。

## 结论

- 扩展前缓存连续覆盖 **2020-10 至 2021-12，共15个月**。2021年12个月全齐，且有完整的2020-12作为2021-01目标月的前置事件月；因此2021全年目标月所需的原始月档案均已在本地。无需为2021再取整月档案。
- 原始响应共69,054条，其中 `document_type=article` 有59,967条；选择台账固定每月30条，共450条。月档案是API当前返回的档案快照，元数据抓取时间为2026-10-03，不是2021年当时保存的文本版本。
- E v2 对目标月当月的文章先按 `pub_date` 截止日过滤，再调用事件选择器，避免从整月已选台账中过滤而让月末新闻影响月初排名。这个日期保护有效，但**不能**证明标题或摘要在当时就是当前缓存中的写法：Archive API返回的字段没有可用编辑时间或历史版本号。
- NYT 官方 Archive API 规格写明需 API key、每日2,000次请求（限额可能调整）、每月响应约20MB；规格未说明当前价格，实际账号价格/额度未核实。规格要求用户阅读并接受专门的 [API Terms of Use](https://developer.nytimes.com/tou) 和署名指引，但该API条款页本次无法读取。另有 NYT 一般 [Terms of Service](https://thenewyorktimeshelpcenter.helpjuice.com/115002797688-Policies/115014893428-Terms-of-Service/)（2026-01-20生效）：1.1列出 APIs 属于其 Services，2.1涉及 AI 系统使用（含 grounding/RAG）与缓存内容。两类条款的适用关系及本研究把摘要/标题放入模型提示的许可范围尚未由本次审计确定；本报告不作法律结论。当前轮只盘点本地数据/离线整理，未将新闻发送给LLM。后续如要进行模型调用，应先核对API专门条款及账号许可，并向NYT确认仍未解决的用途范围。

## 2021全年：覆盖完整，历史文本版本仍未知

目标月M的E v2事件窗是M−1全月及M月截至as_of的新闻。2021全年所需原始月份为2020-12至2021-12，均在扩展前缓存中；故2021年开发/复算不需要补取原始月份。已有台账每月恰好30条，是筛选后样本，不是月档案全集，也不代表新闻覆盖率或居民实际接触率。进入模型的E版本在提示中使用日期与标题；环境记录也会保留摘要等字段。

`build_sce_environment_v2.py` 的 `load_nyt_events_until(month, cutoff)` 会从当月原始缓存筛选满足 `pub_date[:10] <= cutoff.isoformat()` 的文档，然后才按同一套层级、关键词和预算选取。这样不会把截止日之后的当月文章放进候选集，也不会让它们挤占预算。M−1使用已完成月的台账；在as_of落于M月的协议下，使用完整M−1月合理。若其他代码直接拿整月 `events_ledger.jsonl` 后再按日期过滤，仍会有“后续文章改变当月排名/预算”的选择泄漏，应复用原始月档案先筛再选。

日期过滤取NYT `pub_date` 的UTC日期部分，并与as_of的ET日历日期比较。这是有意保守的日期级截止，避免混入截止日之后的新闻；但可能漏掉截止日较晚时段、其UTC日期已进入次日的文章。若研究需要严格到时间戳，须把NYT发布时间转换为ET后与as_of时间戳比较，而非把日期级结果称作精确时点一致。

最重要的历史缺口是文本版本：meta的抓取时间是2026-10-03；`pub_date`是发布日期，不是摘要/标题最后编辑时间。Archive API文档没有说明可查询文章的历史编辑版本，当前响应字段也没有 `updated_date`/修订时间。原始JSON哈希使“本次缓存快照”可复现，却无法还原2021年调查时居民当时可见的标题或摘要。因此此层只能标为“发布时间合规、文本版本未核实”，不能作为完整的历史新闻原文复刻。

## 2022及更长跨度：明确缺月与资源估算

扩展前的本地缓存止于2021-12；**2022-01起均无月档案**。例如目标月2022-01需要2021-12完整月与2022-01当月截止日之前的原始记录，前者有、后者缺。若目标覆盖2020-11至2024-12，则窗口所需原始月为2020-10至2024-12，共51个月：已有15个月，仍缺2022-01至2024-12共36个月。若再扩到2025-12，则在此基础上再缺12个月。

Archive API按月一次返回该月全部记录，官方文档说单月可能约20MB、数千条文档。按本地缓存平均约15.4MB/月估算，36个月约0.55GB；按官方约20MB/月的量级估算约0.72GB。官方规格当前写每日2,000次请求且可能变化，没有给出每分钟固定上限。现有脚本默认相邻下载间隔13秒（约4.6次/分钟），脚本注释另称5次/分钟，但没有在官方当前规格中找到这一每分钟限制依据。执行扩展时保留13秒节奏并监看API条款/响应限流，避免把旧注释当成正式额度。

## 脚本能力、限制与实施顺序

`build_nyt_events.py` 支持 `YYYY-MM..YYYY-MM` 连续月份、缓存复用、`--refresh`、自定义间隔、缓存目录和输出文件。它每次对缺失月份发一个请求，缓存完整响应并记录哈希；后续筛选只取 `document_type == "article"`。当前月按四层排序：头版A1强词全留，随后强词任意版面、头版弱词、其余头版；低层按命中词数量和新近度补到30条。该规则是本项目的新闻显著性代理，不是API官方分类或真人注意力测量。

主要工程限制：

- 脚本在判断缓存前无条件读取仓库`.env`中的key，因此纯离线重建也要求key存在；本审计未读取key。若需零key重建，后续可将“全月命中缓存时无需key”作为实现要求。
- `--sleep`允许传入低于默认值的数值，未强制最小间隔。HTTP错误会按固定间隔尝试最多4次，未遵循429 `Retry-After`；也没有运行时检查API响应状态、`meta.hits`与文档数一致性或字段schema。单月JSON仍先写缓存，再由后续流程使用；扩展前宜补状态/结构验证与可恢复限流逻辑。
- `--refresh`会覆盖对应月份的原始JSON及meta；台账用写入模式覆盖`--out`指定文件。刷新前应保留旧快照哈希和输出，使用版本化目录/输出路径；只拉缺月时也应明确传入完整窗口范围，避免窄范围重建覆盖整段台账。
- `event_id`只哈希URL；API URL迁移或校正可能改变ID。应将稳定文章键、原始月哈希、下载时点、筛选器版本、API规格核查日一起留存。
- 使用API需API key并需接受API条款/署名指引；公开Archive规格未列价格，当前开发者账号的价格/权益未核实。执行任何批量补档前，应由有权限的项目负责人核对当前账号额度、价格和API专门条款。

建议操作顺序：

1. **2021-only**：从现有2020-12至2021-12原始缓存离线重建/核验选择结果，不请求API；如需命令行完全离线，先按上项解除无条件读key依赖。把结果标签保留为 `pub_date` 截止通过、`text_vintage_status=unverified_archive_snapshot`。若标题/摘要要送入真实模型，先通过NYT内容许可核验。
2. **2022起长跨度**：先列出目标期与所需原始月，固定现有15个月快照不覆盖，仅请求缺月。以一年或更短区间断点续跑；每月验证HTTP成功、响应状态、月份、文档数、哈希及meta，再写入新版本台账。仍需按“当月原始全集先截截止时间、后筛选”的顺序生成部分月事件。
3. **API价格与用途条款核验**：Archive API规格未列价格，故当前开发者账号的价格/权益记为“未核实”；配额为每日2,000次且可能调整。官方规格要求阅读API专门条款和署名指引；API专门条款URL为 [`https://developer.nytimes.com/tou`](https://developer.nytimes.com/tou)，署名指引为 [`https://developer.nytimes.com/attribution`](https://developer.nytimes.com/attribution)，本次均无法读取，故无可核实的专门条款章节号。另行参考的一般Terms页面（2026-01-20生效）第1.1节将 APIs 列入Services，第2.1节说明内容及AI系统用途，第2.3节说明复制/存储；它与API专门条款的适用关系及当前模型提示用途的范围仍待确认。这里只登记待核事实，不作法律结论。后续如要做模型调用，应先查看API key账户所绑定条款和许可，再决定是否需要向NYT询问或取得书面许可。[NYT一般服务条款](https://thenewyorktimeshelpcenter.helpjuice.com/115002797688-Policies/115014893428-Terms-of-Service/)、[Archive API规格](https://github.com/nytimes/public_api_specs/blob/master/archive_api/archive_api.md)
