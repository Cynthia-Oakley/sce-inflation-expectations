# 从SCE家庭到个人信息环境：匹配原型与下一步

2026-10-19。**本轮已完成六期576个人月的历史家庭核查、概率采购角色分配、新闻与价格信息菜单及随机对照准备。新增API调用、模型回答、Q9拟合和费用均为0，正式配置未变。**这次验证的是匹配和输入能否可靠构造，尚未检验SCE拟合是否改善。

## 一、先把传导关系说清楚

人口和家庭构成 → 可能承担的购物责任 → 经常接触的商品与信息 → 当时对物价的感受 → 未来12个月预期。

其中前两步可以借助ATUS资料；最后两步仍是需要检验的行为机制。不能从“主要买菜者”直接跳到“通胀预期应高几个点”，也不能把全国食品CPI当作这个人的实际购物涨幅。

新闻是另一条接触途径：新闻关注倾向 → 消息广度；住房、就业和购物责任 → 主题接触概率。一个人可以很少读财经新闻，却经常买菜。这两条途径不能由一个学历或数理标签全部决定。

文献依据：[D’Acunto等，JPE 2021](https://doi.org/10.1086/713192)发现购买接触频率和涨价显著性与通胀预期有关；[D’Acunto等，PNAS 2021](https://doi.org/10.1073/pnas.2008534118)将家庭购物分工与预期差异联系起来。它们支持上述路径，不提供本项目的精确篇数、信息条数或个人匹配真值。

## 二、SCE的家庭信息实际能用到什么程度？

核查对象为2020-09、2021-09、2022-06、2023-12、2024-10、2025-03，各96人，共576个人月、567位受访者。逐人只用目标月之前的家庭题，没有读取本期通胀答案；沿用既有A线人口底表，不将本工作称作B线人口外推。

- **545/576（94.6%）**有可沿用的本人过去家庭构成；记录距目标月最短1个月、中位5个月、最长12个月。不是545份当月重新测量的家庭名册。
- 其余31个未强行补出人数，包含搬家后没有完整新名册而停用旧全户状态的情况，并不等于原始文件从来没有问过家庭构成。
- 17个记录有非亲属同住；原先为CE使用的“剔除非亲属的家庭人数”不能直接当ATUS全住所人数。
- 有效家庭记录中33个不能确定全户有无未成年人；加上31个无可用构成，共64个儿童状态未知。原因是SCE记录本人子女年龄，却不逐一记录其他亲属/室友的年龄；没有本人未成年子女不等于住所没有孩子。
- 还有一个SCE年龄组缺失，按未知维度处理，不把它默认为年轻人。

逐期可用家庭构成为**93、90、89、92、90、91/96**。原始SCE题见本地问卷第33、36—37页：Q45new和D2new包括八类同住者；D1的“家庭是否相同”说明却排除非亲属。因此即使D1回答相同，也不能声称室友人数已重新确认。程序分别保存全住所人数、亲属家庭人数、来源月、记录年龄、变更/搬家标记。

## 三、怎样匹配：同类家庭的概率，不是寻找同一个真人

使用ATUS 2022年五档购物承担程度：完全不承担、少量、部分、大量、全部。先按**年龄组、全住所人数、有无未成年人**寻找同类供体，计算EH调查权重下的角色比例。某个SCE维度未知，就不拿该维度限制供体，而不是将未知当作“没有孩子”。

条件分布按固定规则平滑：

`角色概率 = n/(n+20) × 同类家庭加权比例 + 20/(n+20) × 来源总体加权比例`

这里n为供体实际记录数，20沿用前轮固定值；不是由本期SCE误差调出的参数，也不是严格按复杂抽样推导的贝叶斯后验。本次最小同类供体数10、中位984；但加权有效样本量最小仅6.28，不能只凭“有供体”就认为每个概率都很精确。

每个人使用固定随机分位从概率分布抽取一个合成角色，跨重复不重抽；家庭信息变化时允许概率和角色改变。保留三个预定分配种子，不从结果中选择“最好种子”。2016三档原题另存为独立敏感性候选，没有强行等同于新五档。

### 收入是否也应该加？本次检查结果

在已经看过的2022→2023外部切分中，按同样的固定平滑规则比较，概率预测的对数损失越低越好：

- 年龄＋家庭人数＋儿童：**1.3877**。
- 再加收入：**1.3928**，没有改善。
- 再加收入、学历、地区：**1.4450**，并使21.8%的评价权重落在供体不足10人的格子。

这是探索性诊断，不是新盲测，也不是说收入没有经济学影响。它说明在当前供体量和分组方法下，强制匹配更多字段会损失支持、增加噪声。因此原型先不把收入作为硬限制，更不在没有同口径资产变量时假装做了资产匹配。

### 最重要的统计学限制

这是跨调查的统计匹配。ATUS的一般成年受访者与SCE涉及家庭财务决策的受访者并非完全同一种抽样对象；即使年龄、家庭结构一样，购物责任的分布也未必一样。我们假设同类家庭的角色结构可以部分迁移，**没有识别出某位SCE真人的实际角色**。

[Istat对统计匹配的说明](https://www.istat.it/en/classifications-and-tools/methods-and-software-of-the-statistical-process/process-phase/data-integration/)强调，不同资料里未共同观测的变量之间关系需要额外假设。因此合成角色可以帮助模拟合理的群体差异，却不能凭空恢复真人所有个体差异；尤其不能把随机合成角色与SCE残余误差的关联当成实证发现。购物责任与新闻关注也没有同人联合测量，当前只是分开的合成维度，不宣称真实独立。

## 四、已经做成什么样的信息菜单？

六期576个人月、三个分配种子、匹配/打乱两种采购角色，共生成**3,456个信息菜单**。菜单是未来提示词的可追溯组成部分，**还不是可直接运行的完整引擎提示词**。

### 1. 新闻广度

原型继续使用外部新闻关注的条件概率，保留大量组内随机差异。每期暂用48人3篇、28人8篇、20人20篇，平均8篇，与既有预算可比；这是一组实验名额，不是从ATUS或Andre问卷估出的真实阅读篇数。

另备40篇菜单，六期库存都能提供，但未给任何人指定40篇、未发生新调用。每人的3/8/20/40篇使用同一新闻排序的前缀，避免“多给几篇”同时悄悄更换前面的新闻。原有3篇A1共同背景保留，跨日期重复报道保留。

### 2. 新闻主题

保留50%随机、50%相关加权，相关项仍只提高抽中概率，不保证必读。已知住房与劳动状态可影响相应主题；合成采购承担较多者增加食品主题倾向。没有把“房主”推成“开车的人”，也没有把CE家庭汽油支出推成本人的驾驶记录。

**本次还发现库存约束：**各期现有食品路由标签命中的个人新闻只有**3、8、12、1、2、10篇**，而个人新闻池总数为166—351篇。标签是现有词项路由，不代表严格审定后的全部食品报道；应先检查漏标与候选库覆盖。给人40篇宏观新闻，不会自动补出他经常接触的食品和日用品信息。

### 3. 价格与宏观信息

已把新闻、最新宏观摘要、完整历史统计表分成独立菜单，不由购物责任自动决定是否看完整统计。

当前生活价格原型只使用已有首发食品/在家食品指标，按角色准备0/1/2条细分候选，保留同比、参考期、单位、首发时间和来源。这些条数是待检验的操作化，不是ATUS估计的个人价格知识量。文本如“你承担较多日常采购；你接触到的公开食品资料是……”，**不写成某人的实际收据或已测量的价格感受**，也不预设应把预期上调多少。

现有冻结E仍缺清洁纸品、个人护理等独立价格序列，也没有本人交易价格。因而这一步是采购角色到信息选择的原型，距离真正的个人价格体验还有一段：需核补相应分类价格、消费类别映射，并检验怎样表达可感知的趋势，不能仅换个标题后把整张CPI表再发一遍。

## 五、怎样证明是“匹配”有用，而不是“多给信息”有用？

原型为每期每种子准备同月打乱对照，采购角色和新闻广度分别打乱，保留原来各档人数。打乱只看身份分配和调查权重，不看本期SCE答案。

18个期×种子组合中，匹配/打乱两组的**调查加权平均新闻篇数及食品细分条数差异均控制在1%以内**。这修正了前轮7.49篇与8.02篇不齐的问题，但还不能声称字符数、主题和每条事实的信息价值也相同；后续封存前需检查这些差异。

拟用两项可区分的对照：

1. 同一采购角色视图，改变新闻广度是否与本人特征匹配。
2. 同一新闻广度分配，改变采购角色视图是否与本人特征匹配。

成功需要看到相对随机组的增量，且群体中位数误差、人际分布距离、不同人群误差没有明显互相抵消。仅把模型输出方差拉大，或只赢一个有利月份，都不够。当前没有新的MAE结果，原有主配置与基线读数不变。

## 六、接下来按顺序做

1. **补信息内容的短板。**审核食品/日用品主题在现有新闻库中的漏标和覆盖；检查本地BLS首发存档能否补更细的食品、清洁纸品、护理价格，不先大批重抓或重打标。
2. **核角色到价格表达的合理性。**对照“全国分类指标”“贴近日常采购但仍有来源的简短趋势”，检查有没有把客观统计伪装成本人体验；决定0/1/2细分是否过于机械。暂无可靠真实收据时如实标合成。
3. **完成完整提示词与引擎离线检查。**保持原问卷、上期信念、央行信息和模型参数；对照各组保持同一种宏观统计展示，不同时试删表/加表。核新片段的时间标签、未知处理、加权数量及主题/token差异。
4. **再封存真实对照。**先冻结一项明确机制及独立月份/种子，报告模型、发送字段、调用量与预算。新付费调用另行明确，不复用已执行完的旧授权。

ATUS 2022用于早期目标月，仅是A线回顾性的结构假设；下载到的当前版本也未证明历史公开字节。2016候选同样需要核原始版本和公开日，均不能自动进入严格B事前预测。
