## 1. 两个规模问题分开

历史A线目标为每月SCE实际受访者的加权分布。完整有效权重框架约1200人，Normal＝当月框架人数－Core人数；具体人数逐月变化。增加到五万条展示微观记录只减少随机抽取的Monte Carlo误差，不增加独立信息；本项目主指标直接积分原子权重，不需要为此生成五万人。

最终Core人数依据：中位数近似代价、W1与分组分布、格内有效支持、实际调用成本。人数比例是结果，不把其他项目的比例直接搬过来。

## 2. 已有数据先用

- 82个月真人Core统计留出已有256／384／512三档、两个种子。直接读冻结结果计算规模取舍，不重新拟合Q9或重抽样；真人答案只用于理想统计参照，不进入生产模型。
- 八个月V3.2缓存已完成缩小Core留出，主要是96／192人的回访者小框架。可以检验分布近似，不能由此确定每月完整人群的最佳Core人数。
- 真实调用阶段仅复用完整提示、模型、固定供应商和参数均相同的成功回答，不能仅凭身份/月份相同认定可复用。

## 3. 拟用一次调用比较三档

预定月份仍为202109、202206、202506。每月按原54格分别生成256/保底4、384/保底6、512/保底8三份名册。使用同一SHA排序；**本三期实核逐级包含**，但程序不假定所有未来月份必然包含，通用实现按名单并集计算请求数。

每月取得并集512人一次LLM作答。同一批回答分别投影到256、384、512模型；在较小Core模型中，额外已获取回答也必须隐藏。每种规模使用自己的pi和校准权重。模型、P/E、历史、温度、新闻分配和直接Q8/Q9保持相同。

每月额外抽64人，从所有Core名册并集之外抽取；三期总最多1728个唯一调用位置，一遍，未扣精确缓存。三档各自独立运行同样三期需要4032位置，本设计避免这类重复调用。Normal总人数不算调用人数。

API目的地仍拟为OpenRouter→固定SiliconFlow FP8的DeepSeek V3.2，温度0.5、JSON、关闭思考、最多1024输出token。尚需提示组装、技术干跑与预算授权，没有当前真实调用。

## 4. 三层评价避免混淆

1. **总体对真人：**各规模的Core＋Normal在同一完整波次上评价Q9中位数误差、W1和人际IQR；Q8独立，另外报告Core-only加权参照、真正相邻上期基线。按字段有效真值覆盖说明目标支持，不能混换总体或靠删失败改善分数。
2. **共同留出池对LLM：**64人的LLM回答只作审计，不进入估计。其条件抽样权重参考并集之外的人口池；各规模的预测也限制到同一个池比较。这个池是512Core的Normal，不是256/384方案的全部Normal。小试回答数有限，分组稀疏明确标注。
3. **已有较大Core对照：**较小Core隐藏的额外回答可用于描述在同一已获取LLM框架上的近似损失，须明确目标支持及该框架的抽样权重。不能声称已经获得全1200人的LLM真值，更不能把52万个Normal抽样当独立证据。

主候选τ24及0/8离线敏感性沿既有规则，不为新月份重新择优。比较三种预算属于开发性规模选择；这些月份过去已研究，不能冒称独立盲测。最终生产规模需结合全量预算与可接受的近似代价再决定；384是待验证折中档，非已证实最优。
