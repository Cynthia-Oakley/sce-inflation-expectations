# 夜间全量运行：程序独立执行，Codex按需查看

更新：2026-10-23。**本轮只开发和离线检查，没有启动模型调用，也没有创建付费授权。**

## 1. 两种额度分别负责什么

- **Codex额度：**用于讨论方案、修改代码、查问题与解读结果。下述本地程序没有调用Codex模型、Codex SDK或聊天代理；运行多少批不会逐批消耗Codex额度。
- **OpenRouter余额：**用于程序向指定SiliconFlow路由的DeepSeek V3.2请求模拟回答。余额必须覆盖实际调用；服务端余额和程序内本批预算上限分别生效，充值不会提高脚本预算。

为避开桌面应用的进程回收与终端会话生命周期，正式运行应从**macOS原生Terminal**启动独立后台进程。不是在聊天里保持一个Agent循环，也不要求Codex不断轮询。不能对Codex应用内部工具启动的进程在应用退出后的生命周期作同样保证。

官方[Codex额度说明](https://learn.chatgpt.com/docs/pricing)区分Agent使用额度与API使用；本项目的运行独立性主要来自下述实际代码结构，而非依赖产品触限时会如何处理某个活跃聊天。

## 2. 现有入口已经会做什么

`run_sce_monthly_main_pipeline.py`已经能够一次执行三个阶段：

1. 自动遍历冻结月份并调用模型：前32次最多8并发，格式门槛通过后最多64并发；月份顺序推进，月内并发。不要求每月手动确认。
2. 调用结束后，另起进程读取隔离真值，计算微观、分组与完整波次指标。
3. 另起进程计算全国指标、基线及早期拟权/后期检验的凸组合。

阶段之间不需要Agent转发信息。后两阶段是本地计算，可能包含耗时的Q9密度拟合；API发送完成不等于全部分析完成。该入口不自动生成最终论文、PPT或完整面板，这些后续交付仍需整理。

## 3. 本轮补上的外层管理

入口：`scripts/manage_sce_monthly_main.py`；实现：`experiments/monthly_main_background.py`。只包裹原有管线，**没有改动冻结提示、抽样、计分、供应商、预算或失败规则**。

- `prepare`：检查已有冻结包并保存启动配置，零API，不会生成授权。
- `start`：检查精确人工授权、来源哈希和密钥是否可用；只允许启动一次。使用独立进程会话与文件日志，标准输入断开。
- 后台worker：启动原管线，每10秒从账本**增量**读取进度，原子保存`progress.json`。进度读取故障不要求模型重跑，也不据此补发请求。
- macOS上用`caffeinate`随worker存活防止空闲系统睡眠；不保证合盖、断电、重启或网络故障时继续工作。
- `status`：只读取本地文件，零模型调用。报告已发送、已结束、格式可用、错误、从未发送、暂无本地结果、API已报费用、未知费用预留、每月完成数和当前阶段。心跳过期明确提示，不能仅根据PID存在宣称进程健康。
- 启动锁、worker锁、冻结包执行登记共同拦截重复启动。停止或异常不会自动拉起第二次付费进程。

## 5. 存档粒度与中断边界

模型队列原有三份追加日志：

- `dispatch_private.jsonl`：发请求**前**记录发送意图、提示哈希和费用预留。
- `calls_private.jsonl`：每个请求结束记录原回答、使用量、费用、错误及处理状态，逐条flush。
- `positions_private.jsonl`：本地匿名人口位置与结果对应，逐条flush。

管理目录另保存启动配置、PID、每10秒心跳、外层日志、三阶段日志和最终回执。原始答卷含个人去标识资料，保留在忽略输出目录，不直接上传公开仓库。`progress.json`只含聚合运行计数，不含原答卷或密钥。

这叫**逐请求存档**，不等于突然断电时所有在途回答都能追回。系统崩溃时可能有发送记录却无本地回包，其费用不确定；不能当作从未发送，也不能自动补发以免重复计费。日志flush不是断电时最后一行必定物理落盘的保证。

当前规则仍是：HTTP致命错误/限流、供应商偏离、预算异常或连续三次连接失败等触发停止，停止新发送并收齐在途请求。单次连接失败按原规则留痕，不自动重试。余额不足也会停止；提前充值可减少该风险，但脚本不假定充值成功，也没有本轮新增余额查询API。

**自动完成与自动恢复是两件事。**当前支持无Agent参与的正常全程执行；不支持在致命停止后自行改协议、重启或重发失败。恢复时根据原账本区分已完成、已发无回包、明确失败与从未发送，另生成不覆盖旧记录的续跑清单，按实际情况明确授权。全量专用恢复清单需按中断现场生成和验证，不能把旧三月小试续跑包直接套用。

如果希望夜间连429等错误也能自动冷却后继续“从未发送位置”，那是新的执行策略，必须在最终运行卡中事先设计、验证和批准；本轮没有偷偷开启。
