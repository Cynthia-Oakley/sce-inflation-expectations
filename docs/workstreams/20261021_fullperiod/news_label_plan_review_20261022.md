# Kimi全时段新闻补标方案：定向审阅

审阅对象：[精简标签方案与试点](news_label_slim_pilot_20261021.md)、`scripts/label_sce_news_pool.py`、Flash试点汇总和既有V3.2新闻加载接口。仅阅读和静态核查，没有复跑试点、修改Kimi源码或新增API。

## 结论

**认同分类方向，修复下面三项执行缺口后可准备全量补标。** 模拟用V3.2、打标用官方Flash合理；保留article_id/decision/topics/scope、复用旧标签、每批8篇及温度0都可沿用。无需为此再做一轮模型选择，也不建议全量重标旧库。

本审阅不是新增付费授权。当前方案仍标注用户暂缓；应先生成准确缺口与逐批预算，再确认全量外发范围/硬上限。

## 1. 补标清单须更新并跨窗口去重

方案的43,512来自逐月缺口求和，见`build_sce_fullperiod_coverage.py`的`total_label_gap = sum(...)`。新闻窗口彼此重叠，不能把这个数字直接当成全局唯一待标篇数或按其除8确定请求量。

试点`LABEL_GLOBS`当前仅检出34份文件，未包含已完成的`outputs/sce_v32_new2025_news_acceptance_20261021_v1/labels.jsonl`，也漏掉部分reference/expanded运行的分包。已有冻结的`outputs/sce_v32_new2025_news_preparation_20261021_v2/summary.json`明确记录44份来源、11,473个已知唯一ID；随后又完成2,310篇。因此“旧7,157/缺43,512”是旧库存口径，不能作为最新全量预算。

建议沿已验证的44份显式来源，加新2025验收文件和本轮试点中允许正式采用的新标签，生成版本化来源清单。试点重标/反事实标签不能按文件名字典序自动覆盖正式旧标签；同ID语义冲突进入冲突表，保持旧正式来源优先。新增试点标签须记录V3.2或Flash来源，是否纳入正式库明确选择。

先对所有目标窗口的article_id取并集，再扣除正式已标ID。保留每篇属于哪些月份的映射；同一篇在多个目标月可被使用，**只是不重复付费打标，不删除其跨月时间记录，也不按话题相似度合并不同报道。**

验收只需输出：窗口成员数、全局唯一数、已复用数、唯一新增数、冲突数、请求批数和对应预算，不需重新审计全部NYT原始资料。

## 2. 四字段与真实下游做一次离线兼容

“推理字段不必再由LLM输出”可以成立，但目前还不能写作“删掉对下游完全无影响”：

- V3.2准备器`experiments/post2025_trial.py::source_labels`仍对重复ID直接读取`claim_type`。
- 旧分析入口`news_selection_analysis.py`直接读取`claim_type`和`reason_zh`，旧HTML分析也使用理由字段。
- 新试点`load_old_labels`是按glob遍历后直接覆盖，不是冻结来源优先级的合并器。

全量接入用一个明确标注版本的新适配层：选择/分配只依赖实际需要的字段；缺失解释字段显示“未采集”，不能伪造分类理由或把未知claim_type补成某种观点。兼容旧七字段与新四字段，保留原始标签和来源信息，不重写旧冻结运行。

用一个旧标签月和一个新补标月离线组装最终新闻池及完整Sim提示，检查个人池、共同A1池、ID/发布时间、数量不足回退和摘要去重；无需新的模型调用。共同背景按版面识别的既有规则继续，不因简化打标偷偷改成“所有人只读通胀新闻”。

## 3. 全量执行器的预算、续跑和冻结需补齐

当前试点脚本适合有限试点，不能仅改groups和cap便称全量生产就绪：

- `execute`每次从`spent=0`开始，续跑没有累计已有费用；发生错误时也没有先将可能已计费的请求记入预算。硬上限检查使用`realistic_bound_usd`，不是每请求较保守的`byte_envelope_usd`。应从持久账本恢复“已报告费用＋未知调用预留”，发送前预留本次保守额度。
- `completed_batch_ids`仅看已落下的标签。失败请求在再次execute时会被当作未完成重新发送；写标签中断也可能被当成整批完成。这与“无自动重试”不能直接等同。按槽区分未尝试/已发未明/成功/失败，只有从未发送的槽可自动继续；补发范围须另获允许。
- 当前记录主要保留派生标签和调用摘要，没有完整原始响应/异常响应与发出前状态。须保存可去密的原答、usage及失败现场，便于零API恢复格式与计费核查。
- prepare主要封存批ID，execute重新读取coverage和原文构造输入；应封存完整公开输入或核其内容哈希及来源版本，避免准备后库存变化导致实际发送文字变化。模型/端点/提示词也按新批冻结。
- 现`build_pools`仍无条件访问`pools['consistency']`；“改groups即可全量”尚需真正增加不再运行一致性组的full-period准备模式。全量不重复付费做已完成的300篇一致性样本。

以上优先复用现有一次启动队列和账本规则，或小幅修正当前脚本；不要再造完整调度框架。离线测试至少覆盖：恢复费用、未知计费、失败不重发、部分标签不得算整批成功、输入哈希变化拒绝发送。新接口策略和确切预算准备完再申请全量调用。

## 4. 对试点数字和分类边界的解释

Flash与旧标签的decision一致率87.7%，是**与旧标签的一致性，不是人工真值准确率**，85%也是项目试点阈值。300篇来自一个月份，足以支持限时采用该方案，不能称全时段质量已验证。无需再为达到更高一致率循环改提示。

已存混淆表中37篇decision不同，其中25篇是keep/background互换，12篇跨越保留池与排除池；如果个人新闻只用keep，25篇互换也会改变实际输入，不能全算无关紧要。现有记录无需重新调用即可说明这一点。

“漂移主要来自模型变化”有同一v2.1提示下Flash/V3.2对比作为线索；仍不能把旧Flash别名与当前服务等同为永久相同权重，也不将单一月份一致性当因果证明。

v2.1允许国际央行/能源/贸易消息保留，方向合理；但**相关性与报道地理范围分开**：可相关的外国政策仍可标global/non_us，只有文字支持美国及全球关联时才标us_and_global，不能仅凭研究者觉得“可能影响美国”改地理标签。若改该澄清，标注新提示版本，不再要求新一轮付费一致性试验。

日期仍按原始pub_date/as_of控制；文章更新后的缓存不自动证明历史原文当时可见。保留原文版本证据与未知版本标记，严格B输入按既有规则隔离。不把打标模型知识当新闻事实补充，不向打标请求提供SCE目标真值。

## 可直接给Kimi的工作指令

继续按“官方Flash＋四字段精简标签＋旧库复用”准备全量。先修完整来源索引与跨月唯一补标清单，接通四/七字段的离线Sim组装，再修持久预算/失败续跑/原答与输入冻结。交付一个全量prepare摘要和离线收据，列确切新增篇数、批数、保守预留及硬上限；不要沿43,512旧数字直接execute，也不要重跑300篇试点或重标全部旧库。完成后即可报本批授权并一次自动执行，不必再做全面复审。
