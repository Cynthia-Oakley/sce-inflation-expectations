# 四维Core＋Normal：全量运行前的剩余工作与分工

2026-10-23。准备计划，不是新API授权或已冻结实验。历史82月付费继续暂停。

## 工作量判断

剩余工作中，两项是实质方法研发：54格的条件答卷分布/小格收缩，以及近期无微观段的起点与可得性边界。其余尽量复用既有P/E、初始化、Q9计分、批处理和面板，只改新分层/扩展的接口，不重建引擎或重跑旧结果。

以离线工作为主；小规模真实API端到端验证放在方法与接线完成之后。真人Core留出只能验证统计扩展的可行性，不能代替LLM Core；原六格82月干跑也不能代替新版四维＋Normal的验收。

## 顺序与完成条件

1. **离线确定统计扩展。Codex负责。**固定54格候选、实际分层抽样/校准权重、完整Q8/Q9答卷原子、父池/先验和收缩规则；新人/回访者条件化。比较有限Core规模与旧分层参照，不再搜索全部人口维度。用既定开发期资料拟合/选规则，按人留出，再做时间稳定性检查；不将已见月份称全新盲测。交付明确的分布公式、配置和MAE/W1/条件分布取舍，而不是只给一套能运行的代码。
2. **离线验证LLM回答上的扩展。Codex负责。**优先复用已计分答卷和准确提示/路由缓存；报告旧Core设计与54格目标之间的支持缺口，不能把未知LLM回答当真人回答填入。检查权重比例、加权中位数、供体复用与不确定性、Core/Normal质量不重复和失败后备；不足部分进入下一步小试。
3. **少量真实端到端验收。Codex准备，另报预算。**建议2—3个在看新结果前登记的代表月份，按最终Core候选人数各生成一次；若相同提示/参数的旧答足够则复用，只补必要新位置。验证实际LLM Core经扩展后的总体/分组分布与运行链，不另开多种提示/心理机制。新成员、字段、接收方与总额需另列；当前不能给旧批次自动续跑。若离线条件尚不成立，先修方法，不把小试当反复调参数的工具。
4. **冻结最终配置并重建运行包。Codex负责。**明确93月各段用途、每月不同Core人数、Normal总目标、生成/分配种子、原始/校准权重、无效权重和接口失败规则；宏观惯性权重的拟合/评价窗口及发布时间基线。复用队列/费用预占/断点日志和计分缓存，生成新名单、新真值投影/基线与全量干跑。旧六格41,984份准备包只作旧版本保留，不能直接作为四维结果。
5. **用户审阅完整说明、预算与授权后统一运行。**提供可读的设计说明、关键提示样例、输入边界、已验证/待验证状态、成本及调用数。Normal不算新独立LLM样本；最终调用数主要由月份×Core人数×生成次数决定，不再默认每月512人都由LLM回答。
