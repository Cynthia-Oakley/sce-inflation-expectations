## 评测分两层

1. **2025年较晚月份：个人结构验证。**保留4/6/8/10月候选，用微观真值检验个人分布、旧信念与更新。沿用原回访者机制，避免同时修改输入和模型。它补充已完成的2025-03结果，不能直接证明宏观指标没有训练记忆。
2. **2026年：发布后的总体检验，优先推进。**当前数据覆盖2026-01—09的公开全国汇总，但没有这些月份的真人微观答卷。计划优先准备这一连续段；P由历史人口资料合成，明确初始化来源，再检验总体Q9中位数MAE/RMSE及全国持续性基线。没有微观真值就不报告“真人个人W1”。

2026年无法复制“给本人真实上期答卷、与本人本期实答比较”的旧实验。因此其成绩同时反映人口合成、初始信念、信息环境与模型，不称纯模型同输入对照。若采用自身模拟信念递推，必须从有登记的初始状态开始，逐月运行；必要的2025年末桥接也计入调用范围。不得把未实际生成的上期状态标为simulated_previous。

V3.2发布后仍须锁模型名/供应商/版本证据，并检查新闻是否复述目标月SCE结果；目标答案只进评价。2026历史回放、当时不可得的微观条件和真正事前封存预测分开表述。

## 当前运行到底哪里需要人工

上一批768请求已经是**一次启动、同一队列连续发送**，每完成一个请求自动补入下一个。Agent查看进度不是请求启动条件，四个月之间也不需要Agent发号施令。此前人工小包主要用于网络中断后的授权边界，以及供应商限流后的受控补齐。

仍有人工工作的部分是：冻结样本/输入/预算、获得用户授权、启动进程，以及将调用结束后的评价和报告命令串起来。

## 本轮已实现的串联入口

- `scripts/run_sce_automatic_pipeline.py`：默认仅做本地检查；显式`--execute`才调用已获授权的队列。
- `studies/sce_inflation_expectations/experiments/automatic_pipeline.py`：读取已有授权/文件哈希/并发上限 → 运行全队列 → 完成后调用现有评价器 → 对兼容批次生成现有图文报告 → 保存一次流程收据。
- 不创建新授权、不改提示或统计口径、不生成额外付费技术样本、不自动重试/换供应商/扩大样本。预算与请求数继承已封存账本。
- 接口错误触发原停止规则；异常停止不以完整批次进入评价。评价失败保留已付费答卷，后续只修本地分析，不重跑模拟。
- 当前支持既有逐人评价与原同输入模型比较。**2026汇总评价适配尚未接入**；不能声称新增入口已使2026实验可运行。阶梯并发也尚未接入，现入口使用登记的固定并发数（例如8或16），自动补充请求队列。

8项定向离线检查通过：检查模式不发请求、授权缺失拒绝、并发/哈希不符拒绝、全批结束后自动评价、停止后不评价/不重试、评价失败保留现场、已启动账本拒绝重启。没有重新审计旧数据或运行旧模拟。

准备完成后运行形式为：

```bash
python scripts/run_sce_automatic_pipeline.py --plan outputs/<新批次>/pipeline_plan.json
python scripts/run_sce_automatic_pipeline.py --plan outputs/<新批次>/pipeline_plan.json \
  --execute --out outputs/<新的流程收据目录>
```

`pipeline_plan.json`引用已授权账本、protocol_sha256、评价类型、固定workers、全新评价路径，以及可选的兼容报告路径。它不含密钥。当前没有可执行的2026 plan，不应将上述占位符当作真实运行包。

实际执行可交给本地独立进程，日志由程序持续写入；不需要Agent频繁轮询来维持运行。进程中断后的付费请求状态要核对，不承诺无条件自动恢复。
