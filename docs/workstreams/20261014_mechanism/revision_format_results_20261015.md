# 个人信念更新小试：报告改动增加了概率计算负担

2026-10-15。四期各24人、两组各两次，共384次真实请求完成；没有连接错误、没有重试。按已登记高峰token价记账约**$0.434247**，低于$2上限，非供应商账单。没有新的Event/Population MCP调用。

## 一、先说结论

**这版完整的“十档概率报告改动”不采用。**原因首先是有效率：直接组192份全部有效；改动组192份仅118份有效（61.5%），74份不能使用。

这没有证明“个人信念更新不重要”。它证明当前差值界面不能稳定地让这个模型提交合法概率，不能承担正式模拟。原问题的十档概率本已需要加总100，改成“旧概率+变化”又增加了逐档边界与总变化为0的约束。

## 二、这次真正控制了什么？

四个开发月为2020-04、2021-05、2021-11、2022-03。对原48人名单不看当期答案、按固定种子各抽24人，两次生成。两组共同保留人口、价格/新闻/政策、合成支出及信心、本人上期Q8/Q9和历史摘要，也保留相同的起点说明与未来12个月窗口。

- 直接组填写本期点预期与十档概率。
- 改动组填写点预期的变化及十档概率的变化，程序相加恢复。
- 1人缺上期Q8，保留本人并直接报其本期点预期；两次均走该明确分支，不用Q9均值填补。
- 没有加入刚分析的认知原题、财务Q1、新购买频率或性别。不是新独立时期测试，也不是B连续预测。

## 三、无效回答发生在哪里？程序有没有错？

对192份改动组的原始提示与原回包，用独立Decimal相加再次检查，和转换器判断**零分歧**：

- 69份恢复后出现负概率；其中67份从原本为0的档位继续减去概率。
- 5份十档改动总和不为0。
- 没有概率超过100的情形；这次上述两类不重叠。

例如“上期某档0%，本期该档减少5个概率百分点”，恢复就成了−5%。这个算例仅用于解释，不是展示某个真人的记录。

逐月改动组的有效份数（每月48份）：2020-04为37，2021-05为29，2021-11为17，2022-03为35；直接组各月均48。因此不是一两个异常请求，更不能靠扩样本自动解决。

全部310份有效回包，已从原文本重新恢复或解析，与轨迹内的绝对答案核对一致。原文、转换记录与错误全部保留，未裁剪负概率、未归一化、未追加修复调用。

## 四、有效回答中有没有值得保留的线索？

双方与真人/过去基线共同可评分的115条生成、71个人月中，只有44个人月两次均在共同支持内。以下都是**筛选后有效回答的描述**：

- 群体Q9中心MAE：直接1.181，改动0.933个百分点。
- 跨人分布W1：1.955→1.622个百分点。
- 个人更新分布W1：1.565→1.874个百分点，变差。
- 人际IQR：1.639→2.354，真人同支持约3.235个百分点；宽度接近不等于正确恢复每个人。
- Q8点预期的样本中位数MAE：1.000→0.650个百分点，单列，不和Q9混算。
- 通缩五档全填0占比：约10.0%→51.9%，真人约64.6%。这可能部分继承了上期零档，但不能据此证明正确的信念更新。

同样有效支持上，照抄上期的中心/W1/更新W1约0.924/1.340/2.333；个人历史锚约0.674/1.417/1.636。基线必须和本次同支持比较，不能搬用其他月份或完整样本的更低误差。

**不能把上述中心或W1下降报告为全样本的处理效果。**大量无效回答由处理本身造成，剩下的人和月份权重构成会改变；直接组按同样行比较也不能消除这个选择问题。有效率门槛已经失败，且更新误差点值仍恶化。

## 五、为什么这次没有提供误差改善的显著性区间？

原计划沿用月内按人配对的重抽区间。首次计算发现：两次生成的可用人不同，部分单元很少；某次重抽会完全抽不到该遍可用者，产生零权重，评价程序停止。

我们没有丢掉这些重抽、强行补人或换算法挑显著性，而是记录评价修订：**首先报告事前有效率门槛失败，准确度只留完整行描述，不作区间和全样本推断。**提示、样本、回包和计分不变，修订没有新增API费用。新增一个定向检查确认这条失败分支不会产出误导区间；原9项转换/审计检查也保留。

## 六、这对后续研究意味着什么？

1. 保留先验与个人更新方向；本轮不把完整十档差值格式升级为主机制，也不花剩余预算反复改同一提示。
2. 若以后继续，应先降低任务的额外算术负担，例如只让点预期报告改动、Q9保持原问法，再独立检验；这是未来候选，本轮未准备或运行。
3. 共同有效回答的变化可用于提出假说，不能当作成功证据，更不能以“分布宽了”替代总体中心和更新的验收。
4. **接下来先做导师汇报稿，之后再开展其他机制研究。**用户10月16—23日课程多，日程已压缩，不再把两项新小试和扩大实验排在这几天默认执行。
