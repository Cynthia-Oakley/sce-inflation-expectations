# 新闻机制 V3：实验设计与本地运行说明

2026-10-25。本文用于模拟前确认，不构成启动授权。当前真实模拟调用为0。

**执行补充：**Codex已按第7—8节新增逐请求适配器和Terminal入口，研究输入不变。中午启动请读[Terminal执行附录](TERMINAL_EXECUTION_ADDENDUM_20261025.md)及其离线验收记录，不运行下文旧job级入口。

## 1. 实验要回答什么

主问题是：**居民看到的新闻数量、警示程度、媒体来源和CPI直接相关性变化，能否改善通胀预期模拟，尤其是2021—2022年的低估问题？**

这是路线A的历史条件重建：允许使用当期去标识人口画像和本人真实上期Q8/Q9。不是严格的事前预测，也不排除模型预训练知识造成的历史记忆。

七个月均在A82中出现过，所以只能称探索性机制诊断，不能称独立时间外验证。

## 2. 实验组

R0/Q0/Q1/Q2/Q3是本项目内部名称，不是官方组别。A82是原有82个月主运行，本实验复用其中七个月的原回答，不新增A82调用。

| 组别 | 新闻设计 | 目的与主要比较 |
|---|---|---|
| A82参照 | 原新闻机制，原一遍回答 | 原始参照，不虚构第二遍 |
| R0 | 旧3/8/20篇；只修CPI重要新闻路由 | A82→R0：重要新闻是否被正确放到共同位置 |
| Q0 | 新4/8/16/32篇，其他不变 | R0→Q0：扩大容量并改成四档分配的整体效果 |
| Q1 | Q0＋警示文章权重2.0 | Q0→Q1：警示新闻曝光倾向的影响 |
| Q2 | Q0＋个人新闻约25%来自Fox | Q0→Q2：不同媒体及叙事风格的影响 |
| Q3 | Q0＋CPI直接相关文章权重1.5 | Q0→Q3：直接价格信息配比的影响 |

注意：

- R0→Q0同时改变旧三档与新四档，不能解释为纯粹的一篇新闻增量。
- Q2同时改变媒体和文章文本，不能把效果仅解释为“Fox品牌效应”。
- 2倍警示权重不是实测个人注意概率，只是曝光—传播放大的代理。
- 所有组使用相同人口、非新闻环境和问卷；共同3篇新闻也一致。

## 3. 月份与人口规模

月份：2019-05、2020-09、2021-06、2021-09、2021-12、2022-06、2023-12。

- 2019-05：疫情前参照。
- 2020-09：疫情期。
- 2021年三个月：通胀上行及“暂时性/持续性”争议。
- 2022-06：高通胀阶段。
- 2023-12：后续降温阶段。

每月从A82的512人中按固定哈希抽取96人。不是重新按54格分层，也不是完整全国样本；评价沿用这些人的原设计权重并报告同支持结果。

**96人×2遍不是192个独立居民。**两遍用于观察同一提示下模型随机输出的差异，不能用来扩大人口。

合计：7月×5组×96人×2遍＝6,720次请求，70个任务。

## 4. Population、Environment与Behavior

### Population

沿用A82当月人口：年龄、学历、收入、地区/州、住房、就业、数理等；另含原配置中的合成支出和美联储信心。新入组与回访者按原样本自然存在，不额外制造新人口。

本期真实回答不进入输入；本人真实上期Q8/Q9及更早摘要是路线A明确声明的历史信念输入。

### Environment

保留A82的价格、就业、汽油、政策、信心、食品采购角色等。每月使用原as_of，一般为当月CPI首发日结束时；新闻窗口为上月1日至该截止点。

只替换新闻块及其发布时间说明，其他提示字节必须不变。标签只用于分配，不把“alarming”等标签文字塞进提示；居民最终看到标题、导言和发布时间。

允许网页文本后来发生编辑，不强行要求完全恢复历史原文。Wayback用于证据核查，找到快照不等于逐字历史版本一致；当前文本版本会如实披露。

### Behavior与模型

- OpenRouter → SiliconFlow FP8 → DeepSeek V3.2。
- 温度0.5，关闭思考，JSON输出，直接回答Q8点预期和Q9十档概率。
- 最大输出1024 tokens；无自动重试、无供应商回退。
- 两遍生成种子为42和43，提示相同。
- Q9使用已登记的 `proportional_nonnegative_v1` 后处理和项目冻结近似计分器，不称官方完整算法。

## 5. 新闻数量与匹配机制

### 数量

共同新闻固定3篇。Q0—Q3的总新闻量为4/8/16/32篇，所以个人新闻为1/5/13/29篇。每档每月24人，合计96人，按固定哈希分配。

R0使用原3/8/20档和原分配，保证“只修路由”的对照仍保留。

### 个人匹配

1. 根据住房、就业和合成支出份额得到个人兴趣标签。
2. 相关主题在加权一半中得分×2；另一半保持均匀，避免完全由人物标签决定新闻。
3. 不放回抽取，同一人的新闻不重复。
4. Q0/Q1/Q3使用同一组随机数，只改变注册权重，减少随机样本差异。
5. Q2按个人容量四舍五入分配Fox：1/5/13/29篇中分别0/1/3/7篇，其他来自NYT。
6. Q1的警示权重为2.0，Q3的CPI直接相关权重为1.5；二者不在同一组叠加。

## 6. 评价方式

先看低估/高估，再看平均误差，不能只看一个MAE：

1. signed bias：2021年是否仍系统性低估。
2. 全国Q9中位数MAE：同样人、同权重、同月比较。
3. 个人密度均值MAE、跨人W1和IQR：是否仍然过度同质。
4. Q8单独报告，不与Q9混算。
5. 每月、每遍分别报告，防止平均值掩盖月份或两遍反转。
6. 按四档、上期预期高/中/低、Q2实际Fox接收分层。
7. A82原模型为参照；照抄上期数据也在A82档案中，正式报告应同时列出，避免遗漏更简单的持续性基线。

## 7. 本地Terminal运行方案

### 当前不宜直接启动的原因

当前V3恢复以job为单位：完整job可跳过，未开始job可续；但单个96人job中途断网后，不能安全续该job内部未发送位置。它不满足大批量在本地夜间运行的容错要求。

建议在真实运行前新增**逐请求传输适配层**，复用Codex已有的：

- `monthly_main_resilient.py`：不可改写分段、在途收齐、有界冷却、仅续从未发送位置。
- `monthly_main_console.py`：独立后台进程、10秒进度、`watch`观察和Ctrl+C只退出观察。
- `pending_call_ledger.py`：逐请求意图、原始回复、费用与失败账本思路。

这些模块不是不加修改就能直接套入V3，仍需一个适配器和离线故障测试。官方Core继续做离线输入验收；真实请求须保留同样的提示、模型、费用和原始回复，评价仍接同一套Q9处理。

### 建议冻结的传输策略

- 原生macOS Terminal启动独立后台进程，使用`caffeinate`防止空闲睡眠。
- 首32次以8并发做技术门槛，至少31份格式可用才进入主批。
- 主批初始32并发，健康时最多64；临时故障后按峰值减半，最低8。
- 连接/超时及408/429/500/502/503/504等登记错误：先收齐在途，再冷却30/60/120/240/300秒；优先遵守合法Retry-After。
- 连续未恢复最多5轮、累计冷却最多30分钟、总恢复最多50轮，防止无限等待。
- 凭证、余额、配置、模型/供应商不符、收费异常和哈希变化：立即停止，不自动恢复。
- 已失败请求不自动重发；恢复只处理从未发送位置。已发无回包的费用按未知预留，不冒充未发送。
- 进程崩溃、断电后不会自动重启；人工根据账本恢复。
- 所有续跑累计同一预算，不能每次恢复重新获得预算。

预算估计约$6.21；极端预留$25.69；原协议硬上限$32.11028。实际传输附录需要先离线验证，再由用户重新确认。
