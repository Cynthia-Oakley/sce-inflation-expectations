# 2021 年新闻机制：数据渠道与实施计划

2026-10-25，Kimi 负责新闻机制旁线；Codex 负责主线报告与路线 B。**本文的分组、警示权重与月份规模已被 `NEWS_MECHANISM_2021_PLAN_V2.md` 替代；保留用于追溯数据渠道调研和设计演变。**不是已冻结配置、不是运行授权，也没有新增 API 或模拟调用。

## 1. 既有证据怎样约束这次设计

### 3/8/20 不是新闻扩容

既有随机数量设计按 48:28:20 分配 3/8/20 篇，平均仍是 8 篇。它只改变“谁看得多、谁看得少”，没有改变平均信息量。中心 MAE 曾有小幅改善，但跨人 W1 几乎不变，不能据此继续搜索名额。

本次若检验新闻基数，必须真正提高平均篇数，并单独估计其效果。

### 2021 年不是只有新闻问题

2021 年全国中心 MAE 为模型 0.822pp、历史基线 0.325pp，全年 12 个月均低估。非新闻背景也有明显候选解释：

- 2021-06：居家食品同比 0.7%，总体 CPI 5.0%，差 4.3pp。
- 2021-09：居家食品同比 3.0%，总体 CPI 5.3%，差缩小到 2.3pp。
- 政策摘要保留美联储“暂时性通胀”表述。

因此选择 2021-06＋2021-09：都在高通胀上升阶段，但食品与总体 CPI 的背离程度不同。各组非新闻输入保持完全一致；任何改善仍只能先解释为“新闻输入包的作用”，不能宣称已经解决全部 2021 年问题。

## 2. 数据渠道结论

### 推荐主渠道：Fox 官方 sitemap＋原页短导言＋Wayback 版本核对

- [Fox Business robots](https://www.foxbusiness.com/robots.txt) 和 [Fox News robots](https://www.foxnews.com/robots.txt) 公开列出 sitemap；禁止的是 search、部分 API 等路径，不是整站一刀切。按 sitemap 翻页定位历史 URL，再从原页读取标题、短导言和 `datePublished`，控制请求速率。
- Wayback CDX 用于查最早快照，`id_` replay 用于比对历史标题、导言、`datePublished/dateModified`。已收集的 30 篇候选均找到发布当日或次日快照，说明小样本版本核验可行。
- 只保存 URL、标题、短导言、时间与哈希；全文只用于窗口内核对，不入库、不再分发。 robots 允许不等于正文版权放开。

这条路线免费、无需 API key，适合补 2021 年数月的几十篇候选，也能复用于后续完整月份。

### NYPost：技术上可枚举，但不能忽略自动收集限制

[NYPost robots](https://nypost.com/robots.txt) 列出逐年、逐日 sitemap，技术上比 Google 检索稳定得多；但文件顶部同时明确写着，未经 NYP Holdings 书面许可不得通过自动方式收集内容。

因此：

- 不把 NYPost 自动抓取作为当前生产管线。
- 已有 NYPost 小样保留为探索材料，许可状态如实披露。
- 新批次的外部来源以 Fox 为主；若以后取得书面许可或通过学校图书馆的 Factiva／ProQuest／LexisNexis 等许可渠道，再补 NYPost。
- 不通过更换 User-Agent、镜像或隐藏端点绕过该限制。

### 其他渠道为什么不作为主线

- **GDELT DOC 2：**可按关键词、域名和日期查漏，但只提供标题/URL 等有限字段；实测 Fox Business 可用、NYPost 覆盖很薄，且有速率限制。只作 Fox 的备份查漏，不承担正文和版本核验。
- **Common Crawl：**目标 2021-06 与 2022-06 旬落在爬取空档，且爬取时点不等于发布时点，不适合本批。
- **NewsAPI／NewsCatcher／Event Registry：**免费历史深度或许可不足，商业方案对本批小样本没有必要；也没有历史版本认证优势。
- **Media Cloud：**公开检索 API 已发生下线/维护变化，不作为新项目依赖。
- **NOW corpus：**订阅与批量导出限制不适合。
- **Watson negative_news_sharing：**只有文章特征和 URL，无标题/正文，样本止于 2021-09，不能直接组装提示。

## 3. 推荐实验：五个新组，分别回答五个问题

不做全因子。以修复后的 NYT 组为共同参照，每次只增加一个因素。

| 组别 | 在共同 CPI 路由上的改动 | 主要比较 | 回答的问题 |
|---|---|---|---|
| A82 旧参照 | 原随机 A1、原个人新闻；复用旧答，不新调用 | A82 → R0 | 重要新闻路由是否有增量 |
| R0 | 仅 NYT；CPI salience；原兴趣权重 | 参照组 | 路由修复后的基准 |
| R1 | R0＋警示文章 boost=2 | R0 → R1 | 警示新闻随机加权是否有效 |
| M0 | R0＋Fox 文章占个人新闻 25% | R0 → M0 | 不同媒体及叙事包是否有效 |
| C1 | R0＋CPI 直接相关文章 boost=2 | R0 → C1 | 提高 CPI 新闻占比是否有效 |
| N1 | R0＋个人新闻数量翻倍 | R0 → N1 | 真正增加新闻量是否有效 |

M1“外部媒体＋警示加权”和其他组合不进入首批。只有单项机制出现一致信号，才讨论组合，避免组数膨胀和无法归因。

### R1：警示新闻怎样加权

沿用现有确定性随机加权：50% 均匀抽取＋50% 兴趣/主题加权；在第二部分中，警示文章分数乘 2。不是给每篇随机生成一个权重，也不按真值调权重。

警示标签在运行前冻结：NYT 用固定词表并做人工小样复核，Fox 用逐篇人工标签。负面语气与事实错误分开。

### C1：提高 CPI 占比，而不增加篇数

保持个人文章数量不变，对标题直接涉及 CPI/inflation/prices，或现有标签为 `living_prices` 的文章，在主题加权部分乘 2。它改变的是新闻构成，可能挤出其他主题，必须与 N1 分开评价。

共同三篇已在各组保持一致，并包含 CPI 发布日的重要报道；C1 只改变个人新闻。

### N1：真正增加新闻量

保持共同 3 篇不变，把个人新闻从 0/5/17 篇提高到 **0/10/34 篇**，即总量由 3/8/20 变为 **3/13/37**：

- 平均总篇数由 8 增至 13；
- 个人新闻量翻倍；
- 低/中/高新闻量人群比例保持不变；
- 来源、警示权重、CPI 权重均不变，仍仅用 NYT。

这比继续调整 3/8/20 名额更直接地检验“当前平均 8 篇是否太保守”。它是信息剂量实验，不声称真人真实平均接触量就是 13 篇。

## 4. 月份、人数与调用量

首批只做 **2021-06、2021-09**，每月 96 人、五个新组、两遍：

`2 月 × 5 组 × 96 人 × 2 遍 = 1,920 次物理调用上限`

A82 旧答只做同月、同 agent_id、同权重的参照复算，不重新调用。两遍用于检查生成稳定性，不当作样本量翻倍。

96 人/月足够做探索性的方向和机制筛查，不足以宣称分布验证或独立时间外验证。若出现候选机制，后续全 2021 只保留一个候选组与参照，不把五个组全部扩到 12 个月。

## 5. 评价顺序与停止规则

运行前冻结：

1. **signed bias**：先看低估是否收窄，再看 MAE。
2. 全国 Q9 中心 MAE，与同支持真人、照抄上期及 A82 旧机制比较；Q8 单列。
3. 跨人 W1、IQR：防止只抬高中心却进一步扭曲分布。
4. 按先验高/中/低、原新闻量档和是否实际收到 Fox 文章分层。
5. 两个月、两遍分别报告，不用总平均掩盖单月或跨遍反转。

停止规则：

- 警示或 CPI 加权只增加波动而没有中心收益，不继续搜索更强权重。
- Fox 混合没有增量，不继续扩大媒体名单或调整 25% 比例。
- 新闻扩容没有增量，不继续提高到更高篇数。
- 两个月或两遍方向明显不一致，保留异质性结果，不追加月份追求好看结论。
- 只有方向一致、分布代价可解释的单一候选，才进入全 2021 验证提案；正式采纳门槛由用户与 Codex 在看结果前冻结。

## 6. 实现顺序与交付

1. **数据层：**编写 Fox sitemap 采集器，补 2021-09 完整窗口；用 Wayback 对实际拟用文章做最早快照核对。GDELT 只查漏。NYPost 不进入新增自动采集。
2. **机制层：**把现有 v5 适配器参数化，新增 C1 与 N1；M0 改为跨月一致的 Fox-only，不直接混用旧包含 NYPost 的版本。
3. **执行层：**补 96 人引擎 bundle、执行器格式 prompts、manifest、`2月×5组×2遍=20个job`、唯一 run_id、工程干跑和断点续跑。
4. **评价层：**接 A82 同支持参照、signed bias、MAE、W1/IQR 和分层报告；复用冻结 Q9 计分，不修改 `scoring/sce_q9.py` 的方法。
5. **离线验收：**时点、SCE 泄漏、来源比例、篇数、非新闻字节、哈希、token 与预算全部通过后再给唯一运行命令。
6. **授权后运行：**用户确认外发字段、1,920 次上限和预算帽，才写授权文件并启动；保留所有原始响应、费用与失败记录。

N1 会显著增加部分提示长度，因此旧 v5 的 $8 预算帽不直接沿用。准确估算和保守预算帽在 C1/N1 提示生成后计算，再交用户批准；当前不虚构一个已经算好的费用。

## 7. 当前决定建议

推荐按上述 **五组、两个月、1,920 次上限**实施。它比之前四组方案多回答“CPI 占比”和“真实扩容”两个用户明确关心的问题，同时避免把五个因素组合成全因子。

本计划尚未开始新增采集或执行器修改。下一步经用户确认后，先交付代码和离线验收，再由用户执行运行命令。
