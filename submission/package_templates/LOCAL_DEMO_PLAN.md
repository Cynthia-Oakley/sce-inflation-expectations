# 本地开发视频：录制与呈现方案

更新：2026-10-27。当前为视频制作方案，尚未制作PPT、录音或导出MP4。Kimi正在基于证据材料册整合论文；本方案不修改他的稿件、研究配置、结果或已封存研究包。

## 1. 视频的任务

让评委在五分钟内理解三件事：研究为什么值得做；理论与数据怎样约束一个家庭的模拟；结果有什么用途、在哪些地方仍然失败。论文负责完整论证，视频负责让过程和发现看得见，研究包负责复查。

按[今日官方要求核查](../../docs/workstreams/20261027_final_delivery/official_requirements_check.json)，MP4不超过5分钟，展示实际study流程。用户转交的组委会本地开发说明允许录屏、动画demo或PPT，形式没有硬性限制。下面的片长、画质、镜头和字数都是制作建议，不是赛事追加规定。

建议采用**约4分40秒、7段、6—7张讲解画面＋一段真实Terminal/结果录屏＋中文旁白/字幕**。默认无需露脸；可由作者配音，听感自然比复杂动画更重要。画面逐段制作，最后统一拼接，保留20秒时长缓冲。

### 视频以逻辑为主，执行用三层证据说明

视频的主线是“问题—设计依据—模拟机制—发现与局限”；真实性与可执行性通过短操作段和可追溯记录支撑，不需要在五分钟里重新生成数万份回答。此处是结合本地开发说明作出的呈现建议，不声称组委会已另行豁免任何复现检查。

1. **工程示例：**现场运行20个合成家庭、两步的官方Core接口例，明确它是脚本化接口检查，不是实际LLM能力或正式研究成绩。
2. **真实生成存档：**展示实际批次的脱敏运行配置、完成收据及聚合计数，说明模型、期间、人数、主补次数、费用、失败处理与配置哈希。标注“此前真实运行记录”；不滚屏展示个人答卷、完整提示或新闻全文。配置和收据提供追溯线索，截图/哈希本身不能代替底层审计。
3. **现场聚合复算：**读取包内封存的逐月/逐周聚合数据，重新计算MAE、组合和相应图表，再打开本次生成的receipt。标注“封存聚合复算，0API”；不是从个人十档答卷重新拟合密度、W1或完整微观结构，也不是再次调用LLM。

录屏可采用“README/配置→既有真实运行收据→零API复算→新结果”短链；发现用PPT或图片讲解。完整付费再生成的命令、所需资料/权限及成本另在研究包说明，微观复现尚有限制的部分如实保留。视频不增加收费调用；若以后另做极小真实API演示，需要另定授权，而且不能将其当全量结果的验证。

## 2. 七段分镜及各自只讲的一件事

### 00:00—00:25｜问题：居民预期怎样形成

- 画面：项目标题＋一份真实匿名Q9答卷，配简短的“上期信念→本期信息→概率答卷”示意。
- 旁白重点：研究对象是居民对未来12个月通胀的预期，主目标是SCE回答，而非直接预测下一月CPI。Q8是点预期，Q9是十档概率。
- 让观众带走：这是有真实问卷目标的家庭模拟。
- 素材：[材料册第01节](../../docs/workstreams/20261027_final_delivery/materials_v1/index.html#part-0)、真实Q9图。公式和完整档边界不在此段展开。

### 00:25—01:15｜机制：为什么这样构造代理家庭

- 画面：一张P/E/B流程图，分三次依次出现画像/先验、可见信息、回答/加权；不展示真实人的ID、具体日期、原始人口或受限新闻正文。
- 旁白重点：有限注意与生活价格体验提供设计动机；用人口统计证据选择54格、小格过采样后按人口质量降权。回访者使用严格更早的本人历史，缺失时使用匿名联合供体；A/B的历史信息边界不同。
- 用一句话说明：公开信息不等于所有家庭同样接触，所以新闻/购物价格需匹配和时间筛选。当前4/8/16/32篇、CPI相关度1.5、警示权重1是实验后的操作化，不称文献估计的真实阅读量。
- 角标：DeepSeek V3.2 / 固定SiliconFlow FP8 / temperature 0.5。
- 让观众带走：这不是“让模型扮演普通人”的单个提示词，而是一套可检查的条件与权重。
- 素材：[材料册第02—03节](../../docs/workstreams/20261027_final_delivery/materials_v1/index.html#part-1)。126候选和MCA可点到为止；不展示完整碎石图和全部消融表。

### 01:15—01:50｜执行：真实运行一次复算入口

- 画面：打开最终候选包的README及标准study目录，切到Terminal执行`run.py --mode all`，再打开这次新生成的结果页面与receipt。
- 屏幕标签分开：**20人工程干跑**、**正式研究封存聚合复算**。长等待可剪切，显示“等待过程已压缩”。
- 旁白重点：同一入口核对官方Core接口并重算真实研究聚合；当前演示0API。正式LLM已在先前批次真实运行，完整调用/修复/费用留档。
- 让观众带走：有真实可执行的复现路径，并清楚知道复现到哪一层。
- 此段不现场运行收费模拟，不播放几万次请求的滚动日志，不展示原始个人提示/回复。

### 01:50—02:50｜主结果：中心、分布和组合分开判断

- 画面1：A全时期曲线＋2021放大，指出新版减轻2021低估，但全期仍未超过持续性。用一张小图展示模拟跨人分歧偏窄。
- 画面2：最新B的原始/固定组合/持续性三者。说明原始偏差较大，但先期冻结的小模拟权重组合有局部增量。
- Normal用一个角标或短句交代：A/B已统计扩展到调查规模或约定1300人，扩展不增加独立LLM信息；主数字随最终论文统一Core/Normal口径。
- 让观众带走：宏观中心接近与微观真实不是同一个标准；组合改善不是原始模拟全面胜出。
- 素材：[材料册第04—06节](../../docs/workstreams/20261027_final_delivery/materials_v1/index.html#part-3)。不要同时挤入全部Q8/Q9/W1/IQR表和所有敏感性。

### 02:50—03:35｜周度：探索高频更新的价值

- 画面：47周动态曲线；先强调公开历史SCE发布后的校准点，再放大3月上行和9月漏判。
- 旁白重点：固定300户、周期内个人状态递推；主评价仍是11个月的最后预定周点。原始MAE0.1516pp、持续性0.1727pp；这里“原始”没有输出层线性组合，但用了已经公开的历史SCE校准先验。
- 同屏保留：5/11个月改善、9月漏报；不把47个周点当47个独立真实目标。
- 让观众带走：可以提供月内信号，仍有明确失败月份。
- 素材：[材料册第08节](../../docs/workstreams/20261027_final_delivery/materials_v1/index.html#part-7)。月度自主链后段漂移只用一句话说明，不另占一张完整图。

### 03:35—04:05｜经济用途：信贷是局部线索

- 画面：循环信贷三个期限的小折线；旁边一行“原始模拟5/12项改善，其他结果混合；简单基线仍强”。
- 旁白重点：输入是月度模拟指标，不是刚才的周度指标；同结构回归中，用原始模拟替代官方SCE，信贷1/2/3月RMSE改善3.55%/8.17%/1.69%。
- 让观众带走：除贴合调查之外，有应用探索，但还没有普遍预测优势。
- 素材：[材料册第09节](../../docs/workstreams/20261027_final_delivery/materials_v1/index.html#part-8)。不逐个朗读所有数字，保留图和一条重点即可。

### 04:05—04:40｜结论：贡献与边界同时落地

- 画面：三条贡献＋一条局限说明，末尾给study/README与研究包入口。
- 贡献候选：有经验约束的P/E/B与概率问卷流程；中心—微观—动态的跨层验证；周度和信贷的有限增量价值。
- 局限集中说：合成匹配、旧人口与模型知识/历史版本；部分时期已用于探索；没有全期普遍胜过强基线。完整受控微观复现与默认聚合复算区别保持。
- 工作量用“多轮对照→有依据地采纳/放弃→全时段与拓展验证”概括，避免滚动文件名或堆叠代码行数。
- 结束语围绕已经支持的发现，不保证后续能力。

## 4. 真实演示命令

在独立解压的最终候选包根目录，依赖已安装：

```bash
python studies/sce_inflation_expectations/run.py --mode verify
python studies/sce_inflation_expectations/run.py --mode all
```

第一条可在录制前检查；正式镜头只需展示第二条和实际输出。命令已在现有v05包验收；若最终包升级，录制前在新解压目录再核验一次。

`all`包含官方Core的20人、2步脚本化工程例与封存聚合复算，0API。命令打印本次新目录；打开其中`index.html`和`receipt.json`。`dry_run/study.duckdb`属于本次工程例；主研究真实LLM使用独立JSONL账本，不能混称这份示例库是正式512人运行。

## 5. 需要准备的五类素材

1. **讲解画面：**约6—7页，真实Q9、P/E/B、A/B结果、周度、信贷、贡献/边界；每页一个重点，避免整篇论文截图。
2. **旁白和字幕：**约900—1100中文字作起点，包含停顿和读图；以试读计时为准。字幕与旁白从同一稿生成，关键数字/术语逐项校对。
3. **操作录像：**README/study→执行→实际结果→receipt，保留约30—35秒有效画面。可分段录后剪辑，不能伪装付费现场生成。
4. **结果图：**优先复用材料册中的清晰图片；再按视频16:9裁切或重绘，增大图例/数值，只保留该镜头用到的曲线。
5. **最终检查表：**主表数字、样本/指标、来源版本、文件名、MP4、时长、声音、字幕、脱敏和回放。

素材册用于看全，视频用于抓重点。无需为视频新增Simulation或API支出。

## 6. 制作与验收建议

- 建议1920×1080、16:9、30fps；MP4/H.264视频＋AAC音轨，优先兼容常见播放器。这些为技术建议，不是新增赛事硬标准。
- 用蓝/橙/灰黑和线型区分；数字和图例在1080p下可读。图表不只靠颜色传达含义。
- 旁白为主，无背景音乐或低音量均可；不让音乐遮蔽术语。可以整段配音，也可每20—40秒一段，便于修改。
- 录制窗口关闭密钥、余额、个人资料与通知，Terminal不输出环境变量。优先使用干净的解压研究包和公开汇总页。
- 本人露脸和复杂动画均可选。录制可使用macOS自带屏幕录制；剪辑软件按用户熟悉的工具选择，不增加学习负担。
- 最终完整播放一遍，实测≤5分钟、无静音/字幕错位/切边；保留工程文件和可替换的图/音轨。当前方案不是声称已经录制或通过视频验收。

## 7. 下一步的执行顺序

1. 先确认视频的三条主信息及七段分配。
2. 完成逐镜头画面清单与口播草稿，再制作讲解画面。
3. 先录稳定的目录/命令段；论文数字冻结后录结果段和配音。
4. 拼接、字幕和一次试看片，按时长删重复内容，不靠加速旁白塞满。
5. 统一最终论文/视频/研究包证据，导出与验收；最终提交由用户审阅。

Codex可负责分镜、数字核对、讲解画面和剪辑辅助；用户可提供旁白或实际操作录屏。Kimi继续专注论文，双方通过同一数字/图表清单对齐，本轮未向Kimi发送消息。
